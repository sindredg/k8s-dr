# Unattended drill results

Every run of the `Drill` workflow, oldest first. In each drill the workflow stops both primary VMs and then takes no action: the watchdog detects the outage and starts the `Recover` workflow, and the drill returns to the primary only after that run has passed. [Decision 0015](decisions/0015-unattended-drills.md) defines the drill, and the [runbook](runbooks/unattended-drills.md) explains how to read and refresh this table.

The targets are a recovery time of at most 4 hours and a data loss of at most 2 hours ([decision 0002](decisions/0002-recovery-contract.md#measurement)). The primary holds a 2 GiB dataset during every drill, so the restore stage moves a set of about that size.

| Column | Measured from |
| --- | --- |
| Started by | `schedule` for the Monday, Wednesday, and Friday schedule, `dispatch` for a run started by hand |
| Outcome | `passed`: both targets met and the return succeeded. `missed`: the recovery finished outside a target. `failed`: a step failed after the guards. `refused`: a guard stopped the drill before the primary was isolated |
| Detection | The first failed result of any uptime checker after the isolation, to the creation of the `Recover` run that the watchdog started |
| Recovery time | The same first failed result, to the end of the `probe-recovery` stage, when the fixture checks and a write check passed through `git.sindrg.com` |
| Data loss | The last write acknowledged by the primary before the isolation, minus the write that the restored commit belongs to |
| Writes lost | Acknowledged primary writes newer than the restored commit |
| Bootstrap, Restore | The duration of those stages in the recovery's stage timeline |

`make drill-results` rewrites the table from the result files in the Terraform state bucket. Each drill also opens an issue labelled [`drill`](https://github.com/sindredg/k8s-dr/issues?q=label%3Adrill) with its full report and stage timeline.
